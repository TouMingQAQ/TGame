## 1. 目标与约束

为已有游戏 UI 增加手柄控制，使用 Unity Input System 接收输入，不使用 Unity 原生 Button / Selectable 导航。

用户要求：

1. 以 `GamepadUI`（允许重命名）作为核心，统一处理用于 UI 的手柄输入。
2. Gamepad 目录内的代码不引用任何其他非 Unity 项目或第三方代码；.NET 基础库正常使用。
3. 通过附加组件、事件绑定等方式适配已有 UI，不要求替换 Button 或其他现有控件。
4. 支持界面、Tab 等父子聚焦区域，以及区域内部的目标导航。
5. 支持区域共享的移动光标，也支持每个控件自己控制选中指示效果。
6. 交互行为使用独立组件：根据关联目标的聚焦状态接收需要的输入，再通过事件调用现有业务代码。
7. 脚本名称保持简单，确定名称后再实现。

## 2. 当前代码现状

本次讨论前已读取的 `GamepadUI.cs` 仅包含 `TGame.Gamepad` 命名空间下的空静态类，尚无输入、聚焦、导航实现。Gamepad 目录尚无独立程序集定义。

项目已有自定义按钮，因此适配方式不能仅覆盖 Unity 原生 Button。

## 3. 建议组件与命名

以下名称均为候选，尚未由用户最终确认。

| 名称 | 建议形式 | 职责 |
| --- | --- | --- |
| `GamepadUI` | MonoBehaviour | 接收输入，维护有效聚焦路径和界面聚焦栈，判断输入接收资格并分发操作 |
| `GamepadFocus` | MonoBehaviour | 表示聚焦区域，管理子区域、区域内目标、默认目标、导航与恢复规则 |
| `GamepadItem` | MonoBehaviour | 表示导航目标，提供选中状态、可用状态、光标锚点及选中变化事件 |
| `GamepadCursor` | MonoBehaviour，可选 | 区域共享光标，跟随选中目标；自由移动模式待明确 |
| `GamepadAction` | MonoBehaviour | 关联目标，绑定输入操作与触发阶段，通过事件调用已有交互逻辑 |

`GamepadAction` 加入后，确认、按下、抬起等交互事件从 `GamepadItem` 的初步职责中移出。`GamepadItem` 保留选中与取消选中事件，供控件控制自身指示效果。

`GamepadUI` 改为组件是建议方案，便于 Inspector 配置及生命周期管理；是否提供静态访问入口待实现时决定。

## 4. 聚焦区域与选中目标

区分以下状态：

- 当前聚焦区域：决定目前可操作的控件集合，例如界面 A 内的 Tab1。
- 当前选中目标：决定确认等操作面向谁，以及光标定位到哪里，例如 Tab1 内的按钮2。
- 可接收输入状态：目标除被选中外，还必须处于当前有效区域，且未被上层界面阻断。

示例结构：

```text
GamepadUI
└─ 界面 A：GamepadFocus
   ├─ Tab1：GamepadFocus
   │  ├─ 按钮1：GamepadItem + GamepadAction
   │  ├─ 按钮2：GamepadItem + GamepadAction
   │  └─ 滑条：GamepadItem + GamepadAction
   └─ Tab2：GamepadFocus
      ├─ 开关：GamepadItem + GamepadAction
      └─ 物品格：GamepadItem + GamepadAction
```

建议支持显式指定逻辑父区域，默认可从 Transform 层级查找，减少适配现有 UI 时的层级调整。

### 4.1 Tab 切换

界面 A 处理肩键，在 Tab1、Tab2 等子区域之间切换；子区域处理自身内部的目标导航。

切换流程：

1. 记录旧区域最后选中的目标。
2. 清理旧区域未结束的按压或编辑状态，取消其有效选中表现。
3. 通过事件通知现有 UI 逻辑切换 Tab 内容。
4. 进入新区域，恢复最后有效目标，或使用默认选择规则。
5. 更新共享光标及目标自身的选中表现。

顶部 Tab 按钮是否参与方向导航单独配置。肩键切换无需先选中顶部 Tab 按钮。

暂不增加独立 Tab 脚本，由父聚焦区域管理子区域切换。

### 4.2 界面聚焦栈

建议用聚焦栈处理弹窗：打开弹窗时压入弹窗区域，暂停下层区域输入；弹窗关闭后恢复原界面的区域和目标。

模块只管理输入聚焦，不直接决定业务界面的显示、关闭或动画。实际生命周期由原游戏控制，并通过接口或事件同步。

## 5. 输入接收与分发

### 5.1 统一输入入口

Input System 输入只由 `GamepadUI` 接收。其他组件选择关注的逻辑操作，不直接分别轮询手柄或订阅底层输入。

| 候选操作名 | 用途 |
| --- | --- |
| `Navigate` | 十字键或摇杆方向导航 |
| `Submit` | 确认，默认映射手柄 A 键 |
| `Cancel` | 退出编辑、返回或请求关闭界面 |
| `Previous` / `Next` | 肩键切换子聚焦区域 |
| `Point` | 可选，自由光标连续移动 |
| `Scroll` | 可选，滚动内容 |
| 自定义操作 | 详情、次要操作等，由输入配置扩展 |

优先绑定逻辑操作。例如开关监听 `Submit`，按键映射由输入配置统一决定。

### 5.2 分发顺序与消费

```text
GamepadUI
  → 当前目标关联的 GamepadAction
  → 当前 GamepadFocus
  → 父 GamepadFocus
```

某层处理并消费输入后，停止继续传播。同一目标上的多个处理者需要明确顺序，避免同一操作重复触发；具体排序配置待确定。

典型行为：

- 按钮不消费方向输入，由区域进行目标导航。
- 滑条处于编辑状态时消费左右输入，用于修改数值。
- 肩键向父区域传播，由父区域切换 Tab。
- 返回键优先结束当前控件编辑，再交给区域或父区域处理。

同一次输入只分发给该次操作开始时的有效目标。若回调打开弹窗，新弹窗不得再次收到这次确认操作。

### 5.3 输入运行规则

建议第一版覆盖：

- 摇杆死区与方向判定。
- 方向长按的首次延迟、重复间隔。
- 使用不受 `Time.timeScale` 影响的 UI 输入计时。
- 手柄断开、组件禁用或目标失效时清理持续操作。
- 与现有 EventSystem 输入协调，避免手柄同时触发原生导航或重复确认；保留已有鼠标交互。

## 6. GamepadItem：导航目标

建议提供：

- 所属聚焦区域。
- 是否允许导航选中、是否允许交互。
- 光标定位用的 RectTransform、锚点或偏移。
- 可选的上下左右显式邻居。
- 选中、取消选中事件。
- 管理器维护或计算的有效输入资格，例如候选属性 `CanReceiveInput`。

导航支持两种配置：

1. 自动导航：根据方向及目标位置选择合适目标，具体评分算法待实现。
2. 显式导航：指定上下左右目标，优先于自动结果。

默认导航范围限制在当前区域内。边界循环、跨区域导航为可配置行为。

可用状态不能仅检查 GameObject 是否激活，还应支持与原控件的可交互状态同步。通用 Unity 控件可提供适配，自定义控件通过外部接入代码更新状态。

## 7. GamepadAction：独立交互绑定

### 7.1 用户提出的开关场景

一个 `GamepadItem` 对应开关。开关被选中时，按 A 切换状态。切换交互由另一组件承接，该组件根据关联 `GamepadItem` 的聚焦状态决定是否有资格接收所需输入，再通过事件调用现有切换逻辑。

建议配置：

```text
开关对象
├─ 原有开关组件：保存状态并执行切换
├─ GamepadItem：导航选中状态与光标位置
└─ GamepadAction：Submit 按下 → 事件 → 原有开关切换方法
```

| 配置项 | 示例 |
| --- | --- |
| 关联目标 | 当前对象的 GamepadItem，也允许显式引用其他对象上的目标 |
| 输入操作 | Submit，默认映射 A 键 |
| 触发阶段 | 按下 |
| 触发事件 | 绑定原开关的切换方法 |
| 消费输入 | 是 |

执行链：

```text
按 A → GamepadUI 接收 Submit
     → 判断当前目标与输入资格
     → GamepadAction 触发配置事件
     → 原有开关组件切换状态
```

### 7.2 接收资格与注册

建议由管理器统一路由，而非所有组件收到全局广播后各自判断。

`GamepadAction` 启用时注册、禁用时注销。只有同时满足以下条件才接收常规输入：

- 关联目标是当前选中目标。
- 所属区域处于当前有效聚焦路径，且未被上层界面阻断。
- 目标允许交互。
- Action 组件自身处于有效启用状态。

下层界面可以保留最后选中的记录，但弹窗打开后没有输入资格。

### 7.3 触发阶段与中止

建议支持按下、抬起，以及持续操作需要的取消事件；具体枚举名称待决定。

如果目标失去有效选中、区域切换、组件禁用或设备断开，需要通知已开始的操作取消。取消清理不应因目标已经失去输入资格而被跳过。

对于一次按下开始的交互，后续抬起或取消应正确归属于原接收者，不能误发给新选中的目标。

同一次确认选择一种触发路径，例如调用原控件公开方法或绑定业务事件，避免同时调用点击事件和模拟鼠标点击。

## 8. 光标与选中表现

### 8.1 区域共享光标

区域引用独立的 `GamepadCursor`。目标变化时，区域通知光标移动到目标提供的位置。

- 支持立即定位或平滑移动。
- 布局变化、滚动后继续跟随目标位置。
- 逻辑选中在导航成功时立即改变，不等待光标动画结束。
- 区域无目标或被暂停时，根据配置隐藏光标。

这对应用户提出的“子 focus 需要单独的光标控制入口”。

### 8.2 目标自身指示效果

区域可以不配置共享光标。每个 `GamepadItem` 使用选中、取消选中事件，控制自己的边框、箭头或动画。

共享光标和目标自身高亮可以组合使用。

### 8.3 自由移动模式的待确认含义

“会一直移动的光标”尚需明确：

- 共享光标在不同选中目标之间移动；或
- 摇杆直接控制光标在区域内连续移动。

若需要后者，建议由 `GamepadCursor` 接收管理器分发的 `Point` 输入，在指定区域内移动，并通过命中检测更新当前目标。自由移动与方向导航需要避免争用同一输入。命中规则、光标范围和 Canvas 坐标转换待进一步设计。

## 9. 状态恢复与边界行为

| 场景 | 建议规则 |
| --- | --- |
| 首次进入区域 | 有效默认目标优先，否则选择第一个有效目标 |
| 再次进入区域 | 恢复最后有效目标，否则按首次进入规则选择 |
| 当前目标隐藏、禁用或销毁 | 清理选中与持续交互，重新选择有效目标 |
| 区域没有有效目标 | 保留区域聚焦，清空选中并隐藏光标，继续允许肩键与返回 |
| 切换 Tab | 保存旧区域目标，清理交互，进入新区域并恢复选择 |
| 打开弹窗 | 暂停下层输入，清理持续操作；关闭后恢复下层选择 |
| 设备断开 | 取消持续操作，指示效果保留或隐藏策略待配置 |
| 滚动列表选中屏幕外目标 | 提供请求显示目标的入口，由 ScrollRect 适配或外部方法滚动到可见位置 |

## 10. 独立程序集与接入边界

建议新增 `TGame.Gamepad` 程序集，运行时代码放入模块的 `Runtime` 目录。

允许使用 .NET 基础库和 Unity 官方 API，按实现需要引用 Input System、uGUI、EventSystem 等对应程序集；不引用 TUI、TCore、自定义按钮、DOTween、UniTask 或其他项目业务程序集。

业务接入方式：

- Inspector 中绑定 UnityEvent。
- 外部适配脚本调用模块公开 API。
- 自定义控件扩展放在 Gamepad 模块外部，并由外部依赖模块。

实现时检查 `.asmdef` 引用完整性；修改 C# 后按项目规则构建对应模块，达到 0 错误、0 个代码 warning。当前只保存设计文档，未进行实现或运行验证。
